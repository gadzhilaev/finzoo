# Ограничения прототипа и план развития

§5 п.11 ТЗ. Не перечисляются как «ограничения» вещи, которые ТЗ прямо не требует (нет backend, нет банка — это границы проекта).

## Текущие ограничения (факт)

1. **Только локальное хранение** — `SharedPreferences`, ключ `finzoo_player_profile_v1`. Нет облака, аккаунта, sync между устройствами.  
2. **Нет backend / account sync** — соответствует границе MVP (§2.7 / offline).  
3. **Нет банковских и платёжных интеграций** — только игровая валюта (`EconomyRules`).  
4. **Нет удалённого родительского кабинета** — Adult локальный, за арифметическим gate.  
5. **Android как целевая платформа конкурса** — `applicationId` `ru.gadzhilaev.finzo`; iOS в репозитории есть как Flutter-цель, но сдача ориентирована на Android APK.  
6. **Demo-ограничения** — демо-профиль задаёт учебный снимок (в т.ч. ≥5 периодов); это не «живая» многопользовательская сессия.  
7. **Страница книжки не persist** — индекс Book в сессии; прогресс экономики/профиля persist.  
8. **SFX отсутствуют** — toggle звука сохранён; аудиоконтента нет.  
9. **Физический Android-прогон и метрики cold start / response time** — шаблон и чеклист готовы, **факт не заполнен** (ожидает устройства).  
10. **Репозиторий / релизный тег / публичный доступ экспертов** — вне локальной подготовки (см. §7.2).  
11. **Резервное видео** — сценарий в `docs/VIDEO_SCENARIO.md`; файл записи ещё не снят. Презентация: `docs/presentation/Finzo_presentation.pptx` + `.pdf`.

## Что не является ограничением относительно ТЗ

- Отсутствие RuStore **upload** — ТЗ требует черновик карточки локально (§3.3), не публикацию.  
- Отсутствие IAP / рекламы / соцсетей — запрещено границами, не «недоделка».  
- Отсутствие серверной части — не требуется.

## Дальнейшее развитие (возможные направления, не реализовано)

1. Расширение PracticeCatalog и BookContent без смены ядра.  
2. Опциональные лёгкие SFX с уважением `soundsEnabled`.  
3. Persist позиции книжки / учебных флагов, если продукт это потребует.  
4. Публикация в RuStore после подтверждения лицензий ассетов.  
5. Измерение cold start / отклика на целевых устройствах и фиксация в `ANDROID_TEST_REPORT.md`.  
6. Документированный выбор компетенций из Единой рамки (официальный документ организатора) с явными ID, если потребуется жюри.
